# CartShift 1.2.2 — Truthfulness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stop CartShift reporting confident numbers that are wrong — make the dry run resolve dependencies, make unsupported products visible, and warn when entitlements will be left behind.

**Architecture:** Three independent corrections plus one deferred bug. The dry run gains a simulation mode on the existing `IdMapRepository` memo cache, so validation resolves references without writing to the database. `ProductMigrator` stops silently excluding unrecognised product types from its own totals. `PreflightCheck` gains two new advisory checks. None of this changes what a real migration produces.

**Tech Stack:** PHP 8.3 (must be clean on 8.5), PHPUnit 13, WordPress 7.0, WooCommerce 11.0, FluentCart 1.6.0. Vue 3 + Vitest for the admin app.

## Global Constraints

- **PHP 8.3 minimum, zero deprecations/notices/warnings on PHP 8.5.9.**
- **PSR-12, `declare(strict_types=1)`, `#[\Override]` where a parent declares the method.**
- **All SQL values through `$wpdb->prepare`; table names from `$wpdb->prefix`.**
- **English only** in code, comments and UI strings.
- **NEVER run `git commit` or `git push`.** Project rule: only the owner commits. Where this plan says "Commit", **stage only** (`git add`) and report. This overrides the writing-plans skill default.
- **Never edit** `cartshift.php`, `composer.json`, `package.json`, or any version string — the release is stamped separately.
- **Report only off a full unfiltered test run.** A `--filter` run hid a fatal earlier in this project. Gate: `./vendor/bin/phpunit --display-deprecations --display-notices --display-warnings --do-not-cache-result`, plus one `--order-by=random`, plus `npm test`.
- **Baseline to beat: 565 PHP tests / 1852 assertions, 176 Vitest tests, all green.**

## Background — why this release exists

Verified against a real store on 2026-08-07 (WooCommerce 11.0.0, HPOS on, 699 orders, 363 customers, 50 coupons, 30 subscriptions, 25 recognised products):

1. **The dry run reported 21 coupons would be disabled.** The real number is far lower. `SELECT COUNT(*) FROM …cartshift_id_map` after a dry run returns **0** — `validateRecord()` never calls `IdMapRepository::store()`, so every reference lookup fails by construction. The dry run is honest about mapping quality and misleading about consequences — which is exactly the half the 1.2.1 gap policy governs.

2. **The product total read "25 of 25 migrated".** The store has 27 products; 2 are LearnDash `course` products. `ProductMigrator::getProductTypes()` returns `['simple','variable']` plus the two subscription types, and both `countTotal()` and `fetchBatch()` filter on it — so unsupported products are excluded from the denominator, not skipped. They are invisible, which is worse than being skipped, because a skip is at least reported.

3. **41 of 699 orders reference those invisible products**, and the store runs LearnDash + PMPro entitlement bridges that CartShift deliberately does not migrate (see the scope boundary in the design spec).

## Task 1: Simulation mode on IdMapRepository

**Files:**
- Modify: `app/Storage/IdMapRepository.php`
- Test: `tests/Unit/Storage/IdMapRepositoryTest.php`

**Interfaces:**
- Consumes: nothing.
- Produces: `IdMapRepository::enableSimulation(): void`, `isSimulating(): bool`. While simulating, `store()` updates only the memo; `getFcId()` is unchanged and reads the memo first (that behaviour already exists).

`IdMapRepository` already has a per-request memo added in an earlier release — read it before changing anything. `store()` currently writes through to both the table and the memo.

- [ ] **Step 1: Write the failing test**

```php
public function testSimulationModeKeepsMappingsOutOfTheDatabase(): void
{
    $repo = new IdMapRepository();
    $repo->enableSimulation();

    $repo->store(Constants::ENTITY_PRODUCT, '101', 5001, 'mig-1', true);

    $this->assertSame(5001, $repo->getFcId(Constants::ENTITY_PRODUCT, '101'));
    $this->assertSame(
        [],
        array_filter(
            $GLOBALS['_cartshift_test_queries'] ?? [],
            static fn (array $q): bool => $q[0] === 'insert',
        ),
        'Simulation must never write to the id-map table.',
    );
}
```

- [ ] **Step 2: Run it and confirm it fails**

Run: `./vendor/bin/phpunit tests/Unit/Storage/IdMapRepositoryTest.php --do-not-cache-result`
Expected: FAIL — `Call to undefined method …::enableSimulation()`

- [ ] **Step 3: Implement**

```php
/** True while the dry run is resolving references without persisting them. */
private bool $simulating = false;

/**
 * Resolve references in memory only.
 *
 * The dry run must answer "would this order find its customer?" without writing
 * anything. Before this existed the memo stayed empty, every lookup missed, and the
 * dry run over-reported every dependency-driven outcome it was supposed to predict.
 */
public function enableSimulation(): void
{
    $this->simulating = true;
}

public function isSimulating(): bool
{
    return $this->simulating;
}
```

Then, as the first statement inside `store()`, after the memo is updated and before the `$wpdb->insert(...)` call:

```php
if ($this->simulating) {
    return;
}
```

Make sure the memo write happens *before* that early return, or the simulated mapping is discarded.

- [ ] **Step 4: Run tests and confirm they pass**

Run: `./vendor/bin/phpunit --do-not-cache-result`
Expected: PASS, ≥ 566 tests

## Task 2: Dry run registers synthetic mappings

**Files:**
- Modify: `app/Domain/Migration/MigrationOrchestrator.php`
- Modify: `app/Migrator/ProductMigrator.php`
- Test: `tests/Unit/Domain/Migration/DryRunSimulationTest.php` (create)

**Interfaces:**
- Consumes: `IdMapRepository::enableSimulation()` from Task 1.
- Produces: after a dry run, `IdMapRepository::getFcId()` resolves every entity that validated successfully.

`MigrationOrchestrator::processBatch()` has a dry-run branch calling `$migrator->validateRecord($record)`. Read it first.

Synthetic IDs must be unique, non-zero, and obviously fake so they can never be mistaken for real FluentCart IDs in a log. Use a counter starting at `900000001`.

```php

    $this->drain($orchestrator);

    $this->assertNotNull(
        $idMap->getFcId(Constants::ENTITY_PRODUCT, '101'),
        'A dry run must resolve products it already validated, or every downstream '
        . 'restriction check fails and the run over-reports.',
    );
}
```

- [ ] **Step 2: Run it and confirm it fails**

Run: `./vendor/bin/phpunit tests/Unit/Domain/Migration/DryRunSimulationTest.php --do-not-cache-result`
Expected: FAIL — `getFcId()` returns null

- [ ] **Step 3: Implement in the orchestrator**

In `startMigration()`, immediately after `$this->state->start(...)`:

```php
if ($dryRun) {
    // Resolve references in memory so validation answers the same questions a real
    // run would. Nothing reaches the database.
    $this->idMap->enableSimulation();
}
```

`processBatch()` runs in a fresh request for later batches, so re-enable it there too — put the same guard at the top of `processBatch()` keyed on `$this->state->isDryRun()`.

In the dry-run branch, after `$result = $migrator->validateRecord($record);` succeeds:

```php
if ($result) {
    $processed++;
    $this->idMap->store(
        $migrator->entityType(),
        $migrator->getRecordId($record),
        self::nextSimulatedId(),
        $migrationId,
        true,
    );
}
```

with:

```php
/** Deliberately far above any plausible FluentCart id, so a leak is obvious in a log. */
private static int $simulatedId = 900000000;

private static function nextSimulatedId(): int
{
    return ++self::$simulatedId;
}
```

- [ ] **Step 4: Register simulated variations in ProductMigrator**

Order line items and subscriptions resolve `Constants::ENTITY_VARIATION`, which the orchestrator cannot know about. At the end of `ProductMigrator::validateRecord()`, on the success path only, and only when `$this->idMap->isSimulating()`:

```php
// A real run maps one variation per mapped variation row; mirror that so orders
// and subscriptions validated later resolve their variation references too.
foreach (array_keys($mapped['variations']) as $index) {
    $wcVariationId = $wcVariationIds[$index] ?? $wcId;
    $this->idMap->store(
        Constants::ENTITY_VARIATION,
        (string) $wcVariationId,
        900500000 + (int) $wcVariationId,
        $this->migrationId(),
        true,
    );
}
```

Derive `$wcVariationIds` exactly as `processRecord()` does (`$product->get_type() === 'variable' ? $product->get_children() : [$wcId]`).
