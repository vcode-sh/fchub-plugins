# CartShift 1.3.0 — Selective Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let a shop owner migrate a subset of their WooCommerce store — everything, everything from a date, or a hand-picked set — with the consequences of that choice counted and shown before a single record moves.

**Architecture:** One value object describes the scope; one resolver turns it into per-entity SQL predicates and computes the dependency closure; one preview endpoint reports counts and consequences without touching state. The migrators do not learn about scope through their constructors — they read it from `MigrationState` the same way they already read the migration ID, which is what makes retry and resume reuse it for free. Scope predicates compose with the existing keyset cursor as `WHERE id > :cursor AND <scope> ORDER BY id ASC LIMIT n`; nothing about pagination changes. The 1.2.1 gap policy is already correct and shipping, so the closure never has to reason about missing-reference behaviour — it only has to report how often the policy will fire.

**Tech Stack:** PHP 8.3 (must be clean on 8.5), PHPUnit 13, WordPress 7.0, WooCommerce 11.0 (HPOS), FluentCart 1.6.0. Vue 3 Composition API + Vitest for the admin app.

## Background — the four things that will bite you

Read these before Task 1. None of them is in the design spec, and each one has already cost someone a day.

1. **Keyset pagination, not OFFSET.** Every migrator paginates with `fetchBatch(string|int|null $cursor, int $limit)` and reports its position with `cursorFor(mixed $record): string|int`. A scope predicate is an *extra conjunct* in the same query — `WHERE id > :cursor AND <scope> ORDER BY id ASC LIMIT n` — never a post-fetch filter and never an offset. `SubscriptionMigrator` deliberately still uses OFFSET, because `wcs_get_subscriptions()`'s query vocabulary cannot be verified against source in this repository. **Do not "fix" that.** Task 7b adds scope to it the only way that is safe there — and the trap it has to dodge is that filtering *after* the fetch can empty a page the source was still yielding from, which the orchestrator reads as "this entity is finished".

2. **`CustomerMigrator` has a two-phase cursor** — `registered:<user_id>` then `guest:<billing_email>` — with a splice at the boundary. It is the highest-risk part of this release: a mistake there silently skips customers, and nothing in the counters shows it. Task 5 is its own task with boundary tests for exactly that reason.

3. **A dry run writes `is_simulated = 1` rows** into `cartshift_id_map` (schema v5), and every non-simulating read filters them out. The preview and closure code must never count them, and must never be confused by an abandoned dry run's leftovers. Closure queries read WooCommerce tables, not the ID map, which sidesteps this — keep it that way.

4. **Scope lives in `MigrationState`, next to `entity_types`.** Retry and resume must reuse it or a resumed run silently widens. `MigrationState::isCancelled()` deliberately bypasses the memo — do not disturb that while adding scope accessors.

Two smaller ones: migrators resolve the run ID via `$this->migrationId()`, never a constructor property — scope follows the same rule. And `AbstractMigrator::migratedCount()` already exists; nothing here needs a second counter.

**Two things the spec files under 1.3.0 that 1.2.2 already shipped.** Generic unrecognised-product-type reporting is in `PreflightCheck::checkProductTypes()` (result key `unsupported_product_types`, severity `warn`, with an orders-affected count), and the entitlement-bridge warning is in `PreflightCheck::checkEntitlements()`. Neither needs building. Task 8 *reads* the first one; do not write a second copy of it. If either check is missing when you look, that is a finding — report it rather than reimplementing it here.

## The closure, stated once

The spec describes selection flowing downward along "needs" edges. Written out, and this is the definition every task refers back to:

**Seed** (explicit mode only): `P₀` = picked product IDs, `C₀` = picked registered user IDs, `E₀` = picked guest emails.

1. `O` = orders whose buyer is in `C₀ ∪ E₀`, **plus** — only when the owner accepted the upward offer — orders containing any product in `P₀`.
2. `C` = `C₀` ∪ the registered buyers of `O`; `E` = `E₀` ∪ the guest emails of `O`.
3. `P` = `P₀` ∪ every product appearing in any order in `O`. *An order comes complete.*
4. Coupons: **always all of them.** A coupon is cheap and the gap policy already disables one whose restrictions did not survive.
5. Subscriptions: those whose buyer is in `C ∪ E`. Their products are **not** pulled into `P` — a subscription is an instruction, and gap policy 3 migrates it paused rather than dragging a product in behind the owner's back.

**The closure terminates after one round, and that is deliberate.** The customers added at step 2 do not pull their *other* orders in, and the products added at step 3 do not pull orders in (spec: "product → just the product"). Anything else explodes on a real store.

**Consequence of the closure being correct:** scope alone never creates a broken reference. Every gap the receipt reports comes from a record that is *unmigratable* (an unrecognised product type, a deleted WP user) or from a category the closure deliberately leaves open (a subscription's product, a coupon's restrictions). If you find yourself writing a preview count that is structurally always zero, you have found the closure doing its job — say so in the report rather than inventing a number.

**Closure size limit.** `ScopeResolver::MAX_CLOSURE_IDS = 5000`. If a resolved ID set exceeds it, the resolver says so and `/preview` reports it; `/migrate` refuses with 422. Silently degrading to a wider scope is the one outcome this release exists to prevent.

- [ ] **Step 4: Implement `MigrationScope`**

```php
<?php

declare(strict_types=1);

namespace CartShift\Domain\Scope;

defined('ABSPATH') || exit;

/**
 * What the owner asked to migrate.
 *
 * Immutable and dumb on purpose: it holds a choice, it does not resolve one.
 * The closure — which orders follow which customers, which products an order
 * drags in — lives in ScopeResolver, because that needs the database and this
 * needs to be constructible from a REST body in a unit test.
 *
 * Three modes and no more. A record picker was rejected in design: a
 * 50,000-order shop makes it unusable, and letting someone tick orders and
 * products independently invites contradictions the system then has to
 * adjudicate.
 */
final class MigrationScope
{
    public const string MODE_EVERYTHING = 'everything';
    public const string MODE_SINCE      = 'since';
    public const string MODE_EXPLICIT   = 'explicit';

    /**
     * @param list<int>    $productIds
     * @param list<int>    $customerIds
     * @param list<string> $guestEmails
     */
    private function __construct(
        private readonly string $mode,
        private readonly ?string $sinceDate,
        private readonly array $productIds,
        private readonly array $customerIds,
        private readonly array $guestEmails,
        private readonly bool $includeOrdersForProducts,
    ) {
    }

    public static function everything(): self
    {
        return new self(self::MODE_EVERYTHING, null, [], [], [], false);
    }

    /**
     * Build a scope from whatever a REST body or a stored option holds.
     *
     * Never throws. An unusable value is not a reason to fail a migration the
     * owner has already confirmed — it is a reason to fall back to the mode
     * that cannot lose anything, which is "everything".
     */
    public static function fromArray(mixed $raw): self
    {
        if (!is_array($raw)) {
            return self::everything();
        }

        $mode = is_string($raw['mode'] ?? null) ? $raw['mode'] : self::MODE_EVERYTHING;

        if (!in_array($mode, [self::MODE_EVERYTHING, self::MODE_SINCE, self::MODE_EXPLICIT], true)) {
            return self::everything();
        }

        $since = self::normalizeDate($raw['since'] ?? null);

        if ($mode === self::MODE_SINCE && $since === null) {
            return self::everything();
        }

        return new self(
            $mode,
            $mode === self::MODE_SINCE ? $since : null,
            $mode === self::MODE_EXPLICIT ? self::normalizeIds($raw['product_ids'] ?? []) : [],
            $mode === self::MODE_EXPLICIT ? self::normalizeIds($raw['customer_ids'] ?? []) : [],
            $mode === self::MODE_EXPLICIT ? self::normalizeEmails($raw['guest_emails'] ?? []) : [],
            $mode === self::MODE_EXPLICIT && !empty($raw['include_orders_for_products']),
        );
    }

    /**
     * The persisted and wire shape. Keys are contract — MigrationState, the
     * REST controllers and the Vue app all read exactly these.
     *
     * @return array{mode: string, since: string|null, product_ids: list<int>, customer_ids: list<int>, guest_emails: list<string>, include_orders_for_products: bool}
     */
    public function toArray(): array
    {
        return [
            'mode'                        => $this->mode,
            'since'                       => $this->sinceDate,
            'product_ids'                 => $this->productIds,
            'customer_ids'                => $this->customerIds,
            'guest_emails'                => $this->guestEmails,
            'include_orders_for_products' => $this->includeOrdersForProducts,
        ];
    }

    public function mode(): string
    {
        return $this->mode;
    }

    /**
     * The date bound as MySQL wants it: the start of the chosen day, GMT.
     *
     * wc_orders.date_created_gmt is a DATETIME, so a bare Y-m-d compared with
     * `>=` would work by accident and a `<=` would not. Normalising here means
     * no caller ever has to think about it.
     */
    public function since(): ?string
    {
        return $this->sinceDate !== null ? $this->sinceDate . ' 00:00:00' : null;
    }

    /** @return list<int> */
    public function productIds(): array
    {
        return $this->productIds;
    }

    /** @return list<int> */
    public function customerIds(): array
    {
        return $this->customerIds;
    }

    /** @return list<string> */
    public function guestEmails(): array
    {
        return $this->guestEmails;
    }

    public function includesOrdersForProducts(): bool
    {
        return $this->includeOrdersForProducts;
    }

    public function isEverything(): bool
    {
        return $this->mode === self::MODE_EVERYTHING;
    }

    /** A strict Y-m-d, or null. Nothing looser — a fuzzy date bound is a lie. */
    private static function normalizeDate(mixed $raw): ?string
    {
        if (!is_string($raw)) {
            return null;
        }

        $date = trim($raw);

        if (preg_match('/^\d{4}-\d{2}-\d{2}$/', $date) !== 1) {
            return null;
        }

        [$y, $m, $d] = array_map(intval(...), explode('-', $date));

        return checkdate($m, $d, $y) ? $date : null;
    }

    /**
     * @param mixed $raw
     * @return list<int>
     */
    private static function normalizeIds(mixed $raw): array
    {
        if (!is_array($raw)) {
            return [];
        }

        $ids = [];

        foreach ($raw as $value) {
            if (!is_int($value) && !is_string($value)) {
                continue;
            }

            $id = (int) $value;

            if ($id > 0) {
                $ids[$id] = true;
            }
        }

        $ids = array_keys($ids);
        sort($ids);

        return $ids;
    }

    /**
     * @param mixed $raw
     * @return list<string>
     */
    private static function normalizeEmails(mixed $raw): array
    {
        if (!is_array($raw)) {
            return [];
        }

        $emails = [];

        foreach ($raw as $value) {
            if (!is_string($value)) {
                continue;
            }

            // Lower-cased because wc_orders.billing_email is compared under a
            // case-insensitive collation, and a scope that disagrees with the
            // query it feeds is a scope that drops customers.
            $email = strtolower(trim($value));

            if ($email !== '') {
                $emails[$email] = true;
            }
        }

        $emails = array_keys($emails);
        sort($emails);

        return $emails;
    }
}
```

## Task 2: ScopePredicate — composable prepared SQL fragments

**Files:**
- Create: `app/Domain/Scope/ScopePredicate.php`
- Test: `tests/Unit/Domain/Scope/ScopePredicateTest.php` (create)

**Interfaces:**
- Consumes: nothing.
- Produces:
  ```php
  final class ScopePredicate {
      public static function none(): self;                                  // matches everything
      public static function matchesNothing(): self;                        // '1 = 0'
      public static function raw(string $sql, array $values): self;
      public static function intIn(string $column, array $ids): self;
      public static function stringIn(string $column, array $values): self;
      public static function all(self ...$parts): self;                     // AND
      public static function any(self ...$parts): self;                     // OR
      public function isEmpty(): bool;
      public function matchesNoRows(): bool;                                // the flag, never a string compare
      public function sql(): string;                                        // no leading AND, no outer parens
      public function values(): array;                                      // list<int|string>, in placeholder order
      public function andSql(): string;                                     // ' AND (…)' or ''
  }
  ```

The point of `andSql()` is that a caller can splice it into a query string unconditionally and get `''` when the scope is unbounded, which is what keeps the existing queries readable.

**`matchesNoRows()` is a flag on the object, not `sql() === '1 = 0'`.** The two states this class exists to distinguish — "no clause" and "an empty set" — are semantic, and inferring one of them by comparing a rendered SQL string against a literal makes any `raw()` fragment that happens to equal that string silently vanish from an `any()`. Carry the fact explicitly. The awkward name is deliberate: PHP will not let an instance method share a name with the static constructor `matchesNothing()`, and renaming the constructor would churn every call site in Tasks 3, 7b and 8.

**On chunking.** The design spec calls for "explicit ID sets via `IN (...)` chunks". This plan does not chunk, deliberately: `ScopeResolver::MAX_CLOSURE_IDS` caps any resolved set at 5,000, which is one `IN` list well inside MySQL's `max_allowed_packet` and `$wpdb->prepare`'s appetite. Chunking would mean splitting one keyset page across several queries and reassembling the order, which is exactly the kind of thing that drops a row at a batch boundary. If the cap is ever raised past a few tens of thousands, chunking becomes necessary and this decision has to be revisited — say so in a comment on the constant so the link is not lost.

**`WooStorage::orderScopeParts()` is the pattern to follow**: an unprepared fragment plus its ordered values, so the scope and the pagination go through a *single* `$wpdb->prepare()` rather than nesting one prepared string inside another. Read it before writing this class.

```php
<?php

declare(strict_types=1);

namespace CartShift\Domain\Scope;

defined('ABSPATH') || exit;

/**
 * An unprepared SQL fragment plus the values its placeholders want.
 *
 * Same shape WooStorage::orderScopeParts() returns, and for the same reason:
 * the scope has to fold into the *same* $wpdb->prepare() call as the keyset
 * range and the LIMIT, rather than being prepared separately and nested — a
 * prepared string inside a prepared string is how percent signs in real data
 * turn into corrupted queries.
 *
 * Two kinds of nothing, and the difference is the whole point:
 *
 *   none()          — no clause at all; the caller's query is unrestricted.
 *   matchesNothing() — '1 = 0'; the caller asked for an empty set and gets one.
 *
 * An empty IN list rendered as none() is how "migrate these three customers"
 * silently becomes "migrate all of them".
 *
 * @see \CartShift\Support\WooStorage::orderScopeParts()
 */
final class ScopePredicate
{
    /**
     * @param list<int|string> $values
     */
    private function __construct(
        private readonly string $sql,
        private readonly array $values,
        private readonly bool $matchesNoRows = false,
    ) {
    }

    public static function none(): self
    {
        return new self('', []);
    }

    public static function matchesNothing(): self
    {
        return new self('1 = 0', [], true);
    }

    /**
     * @param list<int|string> $values
     */
    public static function raw(string $sql, array $values): self
    {
        $sql = trim($sql);

        // Never flagged, whatever it renders as. A raw fragment that happens to
        // spell '1 = 0' is a caller's deliberate clause, not this class's empty
        // set, and any() must not drop it.
        return $sql === '' ? self::none() : new self($sql, array_values($values));
    }

    /**
     * @param list<int> $ids
     */
    public static function intIn(string $column, array $ids): self
    {
        $ids = array_values(array_map(intval(...), $ids));

        if ($ids === []) {
            return self::matchesNothing();
        }

        return new self(
            self::sanitizeIdentifier($column) . ' IN (' . implode(', ', array_fill(0, count($ids), '%d')) . ')',
            $ids,
        );
    }

    /**
     * @param list<string> $values
     */
    public static function stringIn(string $column, array $values): self
    {
        $values = array_values(array_map(strval(...), $values));

        if ($values === []) {
            return self::matchesNothing();
        }

        return new self(
            self::sanitizeIdentifier($column) . ' IN (' . implode(', ', array_fill(0, count($values), '%s')) . ')',
            $values,
        );
    }

    /**
     * Conjunction. Empty parts drop out; a matchesNothing() part does not,
     * because an AND with an empty set genuinely is an empty set.
     */
    public static function all(self ...$parts): self
    {
        return self::join('AND', $parts, static fn (self $part): bool => $part->isEmpty());
    }

    /**
     * Disjunction. Both empty *and* matches-nothing parts drop out: an OR with
     * an empty set is the other side of the OR, and a none() part would make
     * the whole disjunction unrestricted, which is the wrong direction.
     */
    public static function any(self ...$parts): self
    {
        return self::join(
            'OR',
            $parts,
            static fn (self $part): bool => $part->isEmpty() || $part->matchesNoRows(),
        );
    }

    public function isEmpty(): bool
    {
        return $this->sql === '';
    }

    /**
     * Is this the empty set — as opposed to no clause at all?
     *
     * A flag rather than `sql() === '1 = 0'`. Inferring it from the rendered SQL
     * would make any raw() fragment that spells the same string disappear out of
     * an any(), silently, and the failure would look like a scope that widened
     * for no reason.
     */
    public function matchesNoRows(): bool
    {
        return $this->matchesNoRows;
    }

    public function sql(): string
    {
        return $this->sql;
    }

    /**
     * @return list<int|string>
     */
    public function values(): array
    {
        return $this->values;
    }

    /**
     * Spliceable form: `' AND (…)'`, or `''` when there is nothing to add.
     */
    public function andSql(): string
    {
        return $this->sql === '' ? '' : ' AND (' . $this->sql . ')';
    }

    /**
     * @param array<int, self> $parts
     * @param callable(self): bool $skip
     */
    private static function join(string $operator, array $parts, callable $skip): self
    {
        $sql = [];
        $values = [];

        foreach ($parts as $part) {
            if ($skip($part)) {
                continue;
            }

            $sql[] = '(' . $part->sql . ')';
            $values = [...$values, ...$part->values];
        }

        if ($sql === []) {
            return self::none();
        }

        return new self(implode(' ' . $operator . ' ', $sql), $values);
    }

    /**
     * Column names are never user input here, but strip anything that is not a
     * plausible identifier before it reaches a query string. Same guard
     * WooStorage applies, and for the same reason.
     */
    private static function sanitizeIdentifier(string $identifier): string
    {
        $clean = preg_replace('/[^A-Za-z0-9_.]/', '', $identifier) ?? '';

        return $clean === '' ? 'id' : $clean;
    }
}
```

```php
<?php

declare(strict_types=1);

namespace CartShift\Domain\Scope;

defined('ABSPATH') || exit;

use CartShift\Support\WooStorage;

/**
 * Turns a chosen scope into the predicates the migrators need, resolving the
 * dependency closure on the way.
 *
 * The closure runs downward along "needs" edges and terminates after one round,
 * deliberately: a customer pulls their orders, an order pulls its buyer and all
 * of its products, and there it stops. Products do not pull orders, and the
 * customers an order brought in do not pull *their* other orders. Anything else
 * explodes on a real store, and the design spec is explicit that the result is
 * reported as a total rather than as a queue of decisions.
 *
 * Everything is memoised per instance, and an instance lives for one request.
 * That is on purpose: three closure queries per request is cheap, and a cached
 * closure that outlived the request would let a mid-run scope change go
 * unnoticed — which is precisely the silent widening this release exists to
 * prevent. Do not put this in a transient.
 */
final class ScopeResolver
{
    /**
     * Ceiling on any single resolved ID set.
     *
     * Above this the resolver refuses to answer rather than truncating.
     * Truncating would migrate a subset of what the owner confirmed, which is
     * exactly the class of silent data loss the whole release is against.
     */
    public const int MAX_CLOSURE_IDS = 5000;

    /** @var array{registered: list<int>, guests: list<string>}|null */
    private ?array $closedCustomers = null;

    /** @var list<int>|null */
    private ?array $closedProductIds = null;

    private bool $exceeded = false;

    public function __construct(
        private readonly MigrationScope $scope,
    ) {
    }

    public function scope(): MigrationScope
    {
        return $this->scope;
    }

    /**
     * Coupons always travel whole.
     *
     * A coupon is cheap, and the 1.2.1 gap policy already migrates one whose
     * restrictions did not survive in a disabled state rather than letting it
     * discount the shop. Filtering coupons by scope would add a second way to
     * lose a coupon and no way to notice.
     */
    public function couponPredicate(): ScopePredicate
    {
        return ScopePredicate::none();
    }

    public function exceedsClosureLimit(): bool
    {
        // Force the closure so the flag is answerable before anything is asked
        // of it.
        $this->closedCustomers();
        $this->closedProductIds();

        return $this->exceeded;
    }
}
```

```php
    public function subscriptionPredicate(): ScopePredicate
    {
        return match ($this->scope->mode()) {
            MigrationScope::MODE_EVERYTHING => ScopePredicate::none(),
            MigrationScope::MODE_SINCE      => self::sinceClause($this->scope->since()),

            // subscription for a product that is not coming across migrates
            // paused (gap policy 3), which keeps the subscriber and the billing
            // history and charges nobody.
            default                         => $this->seedSubscriptionPredicate(),

     * The subscriptions an explicit scope selects, by buyer.
     *
     * The guard on the way out is not decoration. ScopePredicate::any() drops

     * survives — so a scope that picked only products, with the upward offer
     * declined, would OR two empty sets into "no clause at all" and migrate

        $closed = $this->closedCustomers();

        return $predicate->isEmpty() ? ScopePredicate::matchesNothing() : $predicate;
```

```php
     * The orders the owner's picks select, before any closure.
     *
     * Three ways in, OR'd: the buyer is a picked registered customer, the buyer
     * is a picked guest email, or — only when the upward offer was accepted —
     * the order contains a picked product.
     *
     * An explicit scope that selects no orders yields '1 = 0' rather than an
     * empty predicate. That is the difference between "no orders" and "all
     * orders", and getting it the wrong way round migrates the entire shop.
     */
    private function seedOrderPredicate(): ScopePredicate
    {
        $parts = [
            ScopePredicate::intIn('customer_id', $this->scope->customerIds()),
```

```php
    /**
     * Everyone who bought one of the orders this scope selects.
     *
     * @return array{registered: list<int>, guests: list<string>}
     */
    public function closedCustomers(): array
    {
        if ($this->closedCustomers !== null) {
            return $this->closedCustomers;
        }

        if ($this->scope->mode() !== MigrationScope::MODE_EXPLICIT) {
            return $this->closedCustomers = ['registered' => [], 'guests' => []];
        }

        $registered = $this->scope->customerIds();
        $guests     = $this->scope->guestEmails();

        // Only the product-driven orders can bring in buyers who were not
        // picked. Orders selected *by* a picked customer are, by construction,
        // that customer's — so the second hop is skipped entirely when the
        // upward offer was declined.
        if ($this->scope->includesOrdersForProducts() && $this->scope->productIds() !== []) {
            $seed = $this->seedOrderPredicate();

            $registered = self::mergeInts(
                $registered,
                array_map(intval(...), $this->closureCol('DISTINCT customer_id', $seed, 'customer_id > 0')),
            );

            // The `customer_id` guard is what keeps the two sets disjoint. Every
            // order carries a billing_email, registered or not, so without it a
            // registered buyer lands in *both* sets — and closure.customers, the
            // number the receipt panel reports as "that also brings in N
            // customers", double-counts every registered buyer the offer pulled
            // in. It also matches how CustomerMigrator's guest phase defines a
            // guest: an order with no user behind it.
            $guests = self::mergeStrings(
                $guests,
                array_map(
                    static fn (string $email): string => strtolower(trim($email)),
                    $this->closureCol(
                        'DISTINCT billing_email',
                        $seed,
                        "billing_email != '' AND (customer_id IS NULL OR customer_id = 0)",

            );

        $this->noteSize($guests);

    /**
     * Every product in every order this scope selects, plus the picked ones.
     *
     * An order comes complete: a EUR 100 order with three line items migrated
     * with two is not a partial migration, it is corrupted books.
     *
     * @return list<int>
     */
    public function closedProductIds(): array
    {
        if ($this->closedProductIds !== null) {
            return $this->closedProductIds;
        }

        if ($this->scope->mode() !== MigrationScope::MODE_EXPLICIT) {
            return $this->closedProductIds = [];
        }

        global $wpdb;

        $ids   = $this->scope->productIds();
        $seed  = $this->seedOrderPredicate();

        if (!$seed->matchesNoRows()) {
            $orders   = WooStorage::ordersTable();
            $items    = $wpdb->prefix . 'woocommerce_order_items';
            $itemMeta = $wpdb->prefix . 'woocommerce_order_itemmeta';

            [$orderScope, $orderScopeValues] = WooStorage::orderScopeParts();

            $rows = $wpdb->get_col($wpdb->prepare(
                "SELECT DISTINCT im.meta_value
                   FROM {$items} oi
             INNER JOIN {$itemMeta} im
                     ON im.order_item_id = oi.order_item_id
                    AND im.meta_key = '_product_id'
                  WHERE oi.order_id IN (
                            SELECT id FROM {$orders} WHERE {$orderScope} AND ({$seed->sql()})
                        )",
                ...[...$orderScopeValues, ...$seed->values()],
            ));

            $ids = self::mergeInts($ids, array_map(intval(...), $rows));
        }

        $this->noteSize($ids);

        return $this->closedProductIds = $ids;
    }

    /**
     * One DISTINCT column off the orders this scope selects.
     *
     * @return list<string>
     */
    private function closureCol(string $projection, ScopePredicate $seed, string $extra): array
    {
        global $wpdb;

        $orders = WooStorage::ordersTable();

        [$orderScope, $orderScopeValues] = WooStorage::orderScopeParts();

        return array_values((array) $wpdb->get_col($wpdb->prepare(
            "SELECT {$projection}
               FROM {$orders}
              WHERE {$orderScope}
                AND {$extra}
                AND ({$seed->sql()})",
            ...[...$orderScopeValues, ...$seed->values()],
        )));
    }

    /**
     * @param array<int, int|string> $values
     */
    private function noteSize(array $values): void
    {
        if (count($values) > self::MAX_CLOSURE_IDS) {
            $this->exceeded = true;
        }
    }

    /**
     * @param list<int> $a
     * @param list<int> $b
     * @return list<int>
     */
    private static function mergeInts(array $a, array $b): array
    {
        $merged = array_values(array_unique([...$a, ...$b]));
        $merged = array_values(array_filter($merged, static fn (int $id): bool => $id > 0));
        sort($merged);

        return $merged;
    }

    /**
     * @param list<string> $a
     * @param list<string> $b
     * @return list<string>
     */
    private static function mergeStrings(array $a, array $b): array
    {
        $merged = array_values(array_unique(array_filter([...$a, ...$b], static fn (string $s): bool => $s !== '')));
        sort($merged);

        return $merged;
    }
```

**`useScope()` is on the interface.** Every migrator in this plugin extends `AbstractMigrator`, so declaring it there alone would compile — but `ScopePreview::__construct` takes `list<MigratorInterface>` and calls `useScope()` on each, and a contract that does not declare the method it is called through is a static-analysis failure waiting to become a fatal the first time somebody writes a migrator that implements the interface directly. Declare it on the interface; `AbstractMigrator` implements it once for everybody.

**Why `useScope()` exists.** A migrator normally reads its scope from `MigrationState`, exactly as it reads its migration ID — which is what makes retry and resume reuse it with no extra code. But `/preview` has to count under a scope that is not running and must not be written anywhere. `useScope()` is the override for that one caller: set it, and `scope()` prefers it over state. Real runs never call it.

**Retry must carry the scope forward.** `startRetry()` calls `$this->state->start(...)`, which mints fresh state — and fresh state means `MigrationScope::everything()` unless the current scope is captured first. On a retry the scope does not actually filter anything (`fetchByIds()` bypasses `fetchBatch()` entirely), so this is record-keeping rather than gating — but a retry whose state reads "everything" is a retry that lies to the next person who looks at it, and to a resume that follows it.

## Task 7b: SubscriptionMigrator scope — the OFFSET page that must not end the entity

**This is the second-riskiest task in the release, after Task 5, and it fails the same silent way.** `fetchBatch()` is the only migrator entry point that filters *after* fetching, and an empty return from it does not mean "no more rows" — it means "this entity is finished". Get that wrong and a paying subscriber never migrates, with nothing in the counters to show for it.

**Files:**
- Modify: `app/Migrator/SubscriptionMigrator.php`
- Modify: `tests/stubs/EntityMigratorStubs.php`
- Modify: `tests/Unit/Migrator/Entity/KeysetSourceQueryTest.php`
- Test: `tests/Unit/Migrator/Entity/ScopedKeysetTest.php` (modify)

**Interfaces:**
- Consumes: `ScopeResolver::subscriptionPredicate()`, `ScopeResolver::closedCustomers()`, `ScopeResolver::scope()`, `MigrationScope::MODE_SINCE`, `MigrationScope::since()`, `AbstractMigrator::scopeResolver()` (Task 4).
- Produces: no signature changes. `countTotal()`, `fetchBatch()` and `cursorFor()` keep their exact contracts.

`fetchBatch()` pages through `wcs_get_subscriptions()` with OFFSET, deliberately: that function's query vocabulary cannot be verified against source in this repository, so it is not given clauses it may silently ignore. **Do not convert it to keyset and do not pass the predicate to it.** Instead:

- `countTotal()` already queries `wc_orders` directly — give it `subscriptionPredicate()`.
- `fetchBatch()` keeps its OFFSET paging and filters the hydrated page in PHP, **inside a loop**, exactly as `OrderMigrator::fetchBatch()` and `CouponMigrator::fetchBatch()` already loop when a whole page fails to hydrate. Read both before writing this.

**Why the loop is not optional.** `MigrationOrchestrator` says it itself, in the comment above the `if (empty($batch))` branch: *"An empty batch is now the \*only\* end-of-entity signal. Under keyset pagination a short batch no longer means 'no more rows'."* A short batch is safe. An **empty** batch is terminal. A PHP-side filter can empty a page that the source was perfectly happy to keep yielding from — 400 subscriptions, a batch size of 50, and the only in-scope subscriber at position 300 means the first page filters to zero, the entity is marked complete, and that subscriber is gone. This is the identical failure Task 5 exists to prevent for customers.

The rule, then, in two halves and both are load-bearing:

1. Return `[]` only when the *raw* page from `wcs_get_subscriptions()` was empty. Otherwise advance and go round again.
2. `$this->nextOffset` advances by the number of rows the source returned, never by the number that survived the filter. A position in the filtered sequence would ask for the same offset for ever the first time a page kept nothing.

```php
    #[\Override]
    public function fetchBatch(string|int|null $cursor, int $limit): array
    {
        if (!function_exists('wcs_get_subscriptions')) {
            return [];
        }

        $offset = max(0, (int) $cursor);

        // Loops only when an entire page filters away to nothing — the same
        // shape OrderMigrator::fetchBatch() and CouponMigrator::fetchBatch() use
        // when an entire page fails to hydrate, and for the same reason.
        //
        // Returning [] here while wcs_get_subscriptions() is still yielding rows
        // would end the entity: MigrationOrchestrator treats an empty batch as
        // the *only* end-of-entity signal. With 400 subscriptions, a batch size
        // of 50 and the one in-scope subscriber at position 300, the first page
        // filters to zero — and a paying subscriber never migrates, with nothing
        // in the counters to show for it.
        while (true) {
            $subs = array_values((array) wcs_get_subscriptions([
                'subscriptions_per_page' => $limit,
                'offset'                 => $offset,
                'orderby'                => 'ID',
                'order'                  => 'ASC',
            ]));

            if ($subs === []) {
                // The source itself is exhausted. This is the only honest way
                // out of this method with an empty array.
                $this->nextOffset = $offset;

                return [];
            }

            // The position advances by what came back, never by what survived
            // the filter. wcs_get_subscriptions() is the one source this
            // migrator cannot express a predicate to — its query vocabulary is
            // not verifiable against source in this repository — so the filter
            // happens after the fetch, and the paging position has to stay a
            // position in the *unfiltered* sequence or a page that kept nothing
            // would ask for the same offset for ever.
            $offset += count($subs);
            $this->nextOffset = $offset;

            $kept = $this->inScope($subs);

            if ($kept !== []) {
                return $kept;
            }
        }
    }

    /**
     * Keep only the subscriptions this scope selects.
     *
     * Returning fewer than were fetched is fine — a short batch is not an
     * end-of-entity signal. Returning *none* is not fine, which is why the only
     * caller loops rather than handing this result straight back.
     *
     * @param list<object> $subs
     *
     * @return list<object>
     */
    private function inScope(array $subs): array
    {
        $resolver = $this->scopeResolver();

        if ($resolver->subscriptionPredicate()->isEmpty()) {
            return $subs;
        }

        $scope = $resolver->scope();

        if ($scope->mode() === MigrationScope::MODE_SINCE) {
            // MigrationScope::since() is GMT. WC_DateTime carries the site
            // timezone, so date('Y-m-d H:i:s') on it renders site-local time and
            // comparing that string against a GMT bound shifts the boundary by
            // the site's offset — silently, and in whichever direction the site
            // happens to be configured. getTimestamp() is the same instant on
            // both sides regardless, so the comparison is on epochs.
            $bound = (int) strtotime((string) $scope->since() . ' UTC');

            return array_values(array_filter($subs, static function (object $sub) use ($bound): bool {
                $created = $sub->get_date_created();

                return $created !== null && $created->getTimestamp() >= $bound;
            }));
        }

        $closed     = $resolver->closedCustomers();
        $registered = array_flip($closed['registered']);
        $guests     = array_flip($closed['guests']);

        return array_values(array_filter($subs, static function (object $sub) use ($registered, $guests): bool {
            $customerId = (int) $sub->get_customer_id();

            if ($customerId > 0) {
                return isset($registered[$customerId]);
            }

            // Lower-cased on both sides: MigrationScope normalises the picked
            // emails the same way, and a case mismatch here drops a subscriber.
            return isset($guests[strtolower(trim((string) $sub->get_billing_email()))]);
        }));
    }
```

**Termination.** The loop ends because `$offset` strictly increases on every iteration that does not return, and `wcs_get_subscriptions()` returns `[]` once the offset passes the end of the source. Do not add a page-count guard; a guard that fires is a truncated migration wearing a safety belt.
