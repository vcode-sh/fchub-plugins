Everything a developer needs to extend, integrate with, or debug FCHub Multi-Currency.

## REST API

All endpoints use the `fchub-mc/v1` namespace. Admin endpoints require `manage_options` capability and a valid `X-WP-Nonce` header.

### Public Endpoints

<Tabs items={['GET /context', 'POST /context', 'GET /rates']}>
<Tab value="GET /context">

Returns the current resolved currency context, including the price-formatting
metadata a client needs to fully re-render prices (not just the code and rate).

Reads `?currency=` from the query string with top priority in the resolver
chain — ahead of the cookie, and ahead of a signed-in visitor's saved account
preference. This makes the endpoint usable for client-side reconciliation:
`currency-projection.js` calls `GET /context?currency=<code>` to re-resolve a
saved localStorage preference on hosts that strip the guest cookie, without
depending on the cookie reaching the server at all.

**Response:**

```json
{
  "display_currency": "EUR",
  "display_currency_name": "Euro",
  "base_currency": "USD",
  "rate": "0.92140000",
  "source": "cookie",
  "is_base_display": false,
  "symbol": "€",
  "decimals": 2,
  "position": "right_space",
  "display_decimal_separator": ".",
  "display_thousand_separator": ",",
  "disclosure_enabled": true,
  "disclosure_text": "Prices shown in EUR are approximate. You will be charged in USD."
}
```

`source` is one of `url_param`, `user_meta`, `cookie`, `geo`, `default` — see
`ResolverSource`.

Every response — this endpoint and `POST /context`, every status — carries
`Cache-Control: no-store`. The response is resolved per visitor from their
cookie, account, and query string, so a cached copy would leak one visitor's
currency to another; a browser or intermediary that ignored this previously
silently served a stale response back to the reconciliation fetch described
below (issue #72). Client code calling this endpoint directly should also pass
`cache: "no-store"` (or equivalent) rather than relying on the header alone —
see the note in [Guest Currency Reconciliation](#guest-currency-reconciliation).

</Tab>
<Tab value="POST /context">

Sets the visitor's currency preference. Saves to cookie and user meta (if logged in). Fires `fchub_mc/context_switched`.

**Request body:**

```json
{
  "currency": "EUR"
}
```

**Response:** Same shape as `GET /context`, plus `code` (a stable outcome slug —
see below), `message`, `currency`, and `persisted`. Also carries
`Cache-Control: no-store` — see the note on `GET /context`.

A code that isn't 3 letters is rejected by the REST argument schema (400). A well-formed code not in the base/display currencies whitelist returns 422 (`invalid_currency`).

</Tab>
<Tab value="GET /rates">

Returns the latest exchange rates for all configured display currencies.

**Response:**

```json
{
  "base": "USD",
  "rates": {
    "EUR": "0.92140000",
    "GBP": "0.79230000",
    "PLN": "4.02150000"
  }
}
```

</Tab>
</Tabs>

### Admin Endpoints

All require `manage_options` and nonce verification.

<Tabs items={['GET /admin/settings', 'POST /admin/settings', 'POST /admin/rates/refresh', 'GET /admin/currencies/catalogue', 'GET /admin/diagnostics']}>
<Tab value="GET /admin/settings">

Returns all plugin settings with defaults merged.

</Tab>
<Tab value="POST /admin/settings">

Saves and sanitises settings. Reschedules the cron job if the refresh interval changed.

**Request body:** Full or partial settings object. Missing keys retain their current values.

</Tab>
<Tab value="POST /admin/rates/refresh">

Triggers an immediate rate refresh from the configured provider. Returns success/failure with the number of rates refreshed.

Returns HTTP 500 if the refresh fails (provider error, lock contention, empty rates).

</Tab>
<Tab value="GET /admin/currencies/catalogue">

Returns FluentCart's full currency catalogue with flag emojis.

```json
[
  {
    "code": "EUR",
    "name": "Euro",
    "symbol": "€",
    "decimals": 2,
    "flag": "🇪🇺"
  }
]
```

</Tab>
<Tab value="GET /admin/diagnostics">

Returns plugin health information: versions, bcmath status, FluentCart/CRM status, rate counts, stale currencies, feature flags.

Also includes event counts and the most-switched currencies when event logging has data.

</Tab>
</Tabs>

## PHP API

### `fchub_mc_format_price(float $basePrice): string`

Converts a base-currency price to the visitor's display currency and returns formatted HTML.

```php
echo fchub_mc_format_price(99.99);
// Output: "€92.14" (when display currency is EUR with rate 0.9214)
```

Falls back to FluentCart's native formatter when the plugin is disabled or the visitor is in the base currency. Uses `bcmul` for precision when bcmath is available.

### JavaScript Globals

```javascript
// Switch currency programmatically (REST call + page reload)
window.fchubMcSwitchCurrency('EUR');

// Re-initialise all switcher widgets after dynamic content load
window.fchubMcInitSwitchers();

// Re-project prices on a specific DOM subtree
window.fchubMcProjectPrices(document.getElementById('my-container'));

// Update every switcher widget's visible "selected" state to a currency code,
// without a REST call or page reload. Used internally by currency-projection.js
// after client-side reconciliation (see below); rarely needed directly.
window.fchubMcSyncSwitcherDisplay('EUR');
```

### JavaScript Events

| Event | Target | Description |
|---|---|---|
| `fchub_mc:context_changed` | `window` | Fired before page reload after currency switch |
| `fchub_mc:context_switch_failed` | `window` | Fired when a currency switch is rejected server-side (module disabled, nothing to persist, invalid currency, rate limited). `detail: { currency, message, status, code }` |
| `fchub_mc:prices_projected` | `document` | Fired after each projection pass |
| `fchub_mc:context_reconciled` | `window` | Fired after `currency-projection.js` corrects a page served with a stale currency context — see [Guest Currency Reconciliation](#guest-currency-reconciliation) below. `detail: { currency, source }` |

## Currency Switcher Widget

### Block Family

The plugin now exposes a small set of currency-related blocks:

- `fchub-multi-currency/switcher`
- `fchub-multi-currency/current-currency`
- `fchub-multi-currency/exchange-rate`
- `fchub-multi-currency/context-notice`
- `fchub-multi-currency/selector-buttons`

### CSS Custom Properties

Override these on `.fchub-mc-switcher` to theme the widget:

```css
.fchub-mc-switcher {
  --fchub-mc-radius: 6px;
  --fchub-mc-border-color: #d0d5dd;
  --fchub-mc-bg: #fff;
  --fchub-mc-shadow: 0 4px 16px rgba(0, 0, 0, 0.12);
  --fchub-mc-transition: 150ms ease;
  --fchub-mc-badge-ok: #12b76a;
  --fchub-mc-badge-stale: #f04438;
}
```

### ARIA Roles

The widget implements the combobox/listbox pattern:

- Trigger: `role="combobox"` with `aria-expanded`, `aria-haspopup="listbox"`, `aria-controls`
- Option list: `role="listbox"` with `aria-label="Select currency"`
- Each option: `role="option"` with `aria-selected` on the active currency
- `aria-activedescendant` tracks the currently focused option
- Unique ARIA IDs per instance for multiple widgets on one page

## Guest Currency Reconciliation

Some hosts run an edge/WAF layer that strips cookies by default on any URL path
that hasn't been explicitly whitelisted, scoped per-path rather than sitewide.
On such hosts, a logged-out visitor's `fchub_mc_currency` cookie never reaches
WordPress on an ordinary page load, so the resolver chain falls through past
`CookieResolver` to geolocation or the store default — even though the browser
still has the cookie and the visitor never changed their mind. Signed-in
visitors are unaffected: their preference lives in user meta, a second,
independent channel `UserMetaResolver` resolves ahead of the cookie.

The plugin adds a client-side fallback that doesn't depend on the
cookie round-tripping through that layer:

1. `currency-switcher.js` mirrors a guest's choice into `localStorage`
   (`fchub_mc_currency`) in addition to the existing cookie/REST persistence,
   gated on `guestLocalStorageEnabled` (mirrors the `cookie_enabled` setting —
   a site that disabled guest persistence outright doesn't get it back through
   a side door).
2. `currency-projection.js` compares that localStorage value against the page's
   baked-in `displayCurrency` on load. It only acts when the page's `source` is
   `cookie`, `geo`, or `default` — never `url_param` or `user_meta`, so an
   explicit link or a signed-in visitor's saved preference is never
   second-guessed by a stale local value.
3. If they disagree, it fetches `GET {restUrl}/context?currency=<code>` — which
   resolves via the URL query string, not the cookie — reassigns the mutable
   projection state in place, clears and re-runs price projection, and calls
   `window.fchubMcSyncSwitcherDisplay()` so the switcher widget's own display
   catches up too. `fchub_mc:context_reconciled` fires on `window` afterwards.
4. The localStorage value is validated against the base currency and enabled
   display currencies baked into the page (mirroring
   `AllowedCurrencyCheck::isAllowedCurrency()`) before it's ever trusted, and
   the server independently re-validates it again via the normal resolver
   chain — a stale or tampered localStorage value can't force an unsupported
   currency.

### The reconciliation fetch must never be cache-servable

Step 3's `fetch()` call passes `cache: "no-store"`, and the endpoint responds
with `Cache-Control: no-store` (see `GET /context` above) — both are load-bearing,
not defensive nicety. Confirmed live on issue #72: with the header alone but no
`cache: "no-store"` on the request, once a given `?currency=X` URL had been
fetched once in a browser profile, the browser served that same response from
its own HTTP cache on every later reconciliation attempt — status 200, no real
round trip — even though the endpoint itself was resolving correctly and a
fresh direct navigation to the same URL always returned the right answer. The
page kept silently settling back on the stale currency. If you build your own
client against this endpoint for the same purpose, set `cache: "no-store"` (or
your HTTP client's equivalent) rather than relying on the response header
alone — a response already cached from before the header shipped would still
be reused without it.

## Feature Flags

Internal flags stored under the `fchub_mc_feature_flags` option. Not exposed in the settings UI — visible in the Diagnostics tab.

| Flag | Default | Controls |
|---|---|---|
| `js_projection` | `true` | Whether `currency-projection.js` is enqueued. Disable to turn off client-side price rewriting. |
| `geo_resolver` | `false` | Whether the geolocation resolver is included in the chain. Not yet production-ready. |

## GDPR / Privacy

The plugin registers with WordPress's privacy tools:

### Personal Data Exporter

Exports for a given email address:
- User meta `_fchub_mc_currency` (preferred currency preference)
- All `fchub_mc_event_log` rows for the user (event name, timestamp; paginated at 50 per page)

### Personal Data Eraser

Deletes for a given email address:
- `_fchub_mc_currency` user meta
- All `fchub_mc_event_log` rows for the user
