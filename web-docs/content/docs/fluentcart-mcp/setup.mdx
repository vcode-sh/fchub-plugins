Three things happen: FluentCart MCP gets a WordPress Application Password, your client starts the
same MCP command, and you ask one read-only question to prove the connection. Package-manager
theatre has not been invited.

## Generate an Application Password

Every setup path needs this. It's how the MCP server authenticates with your store — no actual login password involved.

<Steps>
<Step>

**Go to WordPress admin → Users → Profile**

Scroll down to the **Application Passwords** section. Type a name — `FluentCart MCP` works — and click **Add New Application Password**.

</Step>
<Step>

**Copy the password immediately**

It looks like this: `aBcD eFgH iJkL mNoP qRsT uVwX`

<Callout type="warn" title="One Chance">
WordPress shows this password exactly once. Close the page without copying and you'll need to generate a new one.
</Callout>

</Step>
<Step>

**Have your three values ready**

| Value | Example |
|-------|---------|
| **WordPress URL** | `https://your-store.com` |
| **Username** | `admin` |
| **Application Password** | `aBcD eFgH iJkL mNoP qRsT uVwX` |

The URL is the root of your site — no trailing slash, no `/wp-admin/`, no `/wp-json/`. The username is your WordPress login name, not your display name.

<Callout type="info" title="Least Privilege Works Fine">
The server inherits whatever that WordPress user can do and nothing more, so a store-manager-style role with FluentCart permissions is a perfectly sensible choice — you don't have to hand your AI the keys to the entire site. A user with no FluentCart permissions at all will collect 403s, which is the system working as designed rather than a bug. Pair a narrow role with the default read-only write mode and the blast radius is roughly zero.
</Callout>

</Step>
</Steps>

## Choose Your Client

| Client | Best route | Separate install? |
|---|---|---|
| **ChatGPT Desktop** | **Settings → MCP servers → Add server** | Node.js 24+, but no global package install |
| **Codex CLI** | `codex mcp add` | Node.js 24+, but no global package install |
| **Codex IDE extension** | Shared Codex configuration | Node.js 24+, but no global package install |
| **Claude Desktop** | MCPB extension | No separate Node install |
| **Claude Code** | `claude mcp add` | Node.js 24+, but no global package install |
| **Cursor** | Global `mcp.json` | Node.js 24+, but no global package install |
| **VS Code with GitHub Copilot** | User or workspace `mcp.json` | Node.js 24+, but no global package install |
| **Windsurf** | `mcp_config.json` | Node.js 24+, but no global package install |
| **ChatGPT web** | OpenAI Secure MCP Tunnel | Private web connection |

These are exact setup recipes, not certification claims. The release's unattended checks cover MCP
Inspector, Claude Code and Docker; a configuration file does not become certification merely by
looking confident.

## Local Client First Run

Skip this section only if you are using the Claude Desktop extension.

<Steps>
<Step>

**Install Node.js 24 or newer**

Check with `node --version`. Local `npx` recipes need Node.js 24; download it from
[nodejs.org](https://nodejs.org) if needed.

</Step>
<Step>

**Save the store credentials once**

```bash
npx -y fluentcart-mcp setup
```

`npx -y` downloads FluentCart MCP on demand and reuses the package-manager cache afterward. It
does not install the package globally. The wizard tests the store and writes the credentials to
`~/.config/fluentcart-mcp/config.json` on macOS/Linux or
`%APPDATA%\fluentcart-mcp\config.json` on Windows with private file permissions.

</Step>
<Step>

**Add the server and verify one read**

Every local recipe below starts the same command:

```text
command: npx
arguments: -y fluentcart-mcp
```

After the client reports the server as connected, ask: *"Show me the FluentCart dashboard stats."*
Store data is the useful proof. A green dot alone is merely a very optimistic dot.

</Step>
</Steps>

## Exact Client Recipes

<Tabs items={['ChatGPT + Codex', 'Claude Desktop', 'Claude Code', 'Cursor', 'VS Code', 'Windsurf', 'ChatGPT web', 'Docker']}>
<Tab value="ChatGPT + Codex">

### ChatGPT Desktop

ChatGPT Desktop, Codex CLI and the Codex IDE extension share MCP configuration on the same host in
`~/.codex/config.toml`. Configure it once and the three clients can use the same server.

1. Open **Settings → MCP servers → Add server**.
2. Name it `fluentcart`, choose **STDIO**, set command to `npx`, and set arguments to
   `-y fluentcart-mcp`.
3. Save, select **Restart**, then type `/mcp` in a chat to confirm `fluentcart` is connected.
4. Ask *"Show me the FluentCart dashboard stats."*

This direct **Add server** route is the shortest OpenAI setup. If you prefer plugin-managed enable
and disable controls, add the repository marketplace:

```bash
codex plugin marketplace add vcode-sh/fchub-plugins --ref main
codex plugin marketplace list
```

Restart ChatGPT Desktop, open **Plugins Directory**, choose the `fchub-plugins` marketplace, and
install `fluentcart-mcp`. The plugin starts the same server and is optional. A repository
marketplace is separate from the universal public directory, so this route does not claim a public
directory listing.

### Codex CLI

```bash
codex mcp add fluentcart -- npx -y fluentcart-mcp
codex mcp list
```

Start a new Codex session, use `/mcp` to confirm the server, then ask the verification question.

### Codex IDE extension

The server added above appears automatically because the IDE extension reads the same
`~/.codex/config.toml`. If you start in the IDE instead, open the gear menu, choose **MCP servers →
Add server**, and enter the same STDIO command. Restart the server, then verify it in the MCP list.

</Tab>
<Tab value="Claude Desktop">

### Claude Desktop extension

Claude Desktop supplies a built-in Node runtime for Node MCPB extensions, so extension users do not
install Node.js separately.

1. Download <McpbDownload /> from the latest GitHub Release.
2. In Claude Desktop open **Settings → Extensions → Advanced settings → Install Extension** and
   select `fluentcart-mcp.mcpb`.
3. Enter the WordPress URL, username and Application Password, then enable the extension.
4. Start a new chat and ask *"Show me the FluentCart dashboard stats."*

The MCPB contains the server's JavaScript and production dependencies. It does not contain a Node
executable; Claude Desktop supplies that runtime.

</Tab>
<Tab value="Claude Code">

Run the credential wizard first, then add the server:

```bash
claude mcp add fluentcart -- npx -y fluentcart-mcp
claude mcp list
```

Start a new session and ask the verification question. `claude mcp list` confirms configuration;
the returned store data confirms the live connection.

</Tab>
<Tab value="Cursor">

Open **Settings → Cursor Settings → MCP → Add new global MCP server** and add this to `mcp.json`:

```json
{
  "mcpServers": {
    "fluentcart": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"]
    }
  }
}
```

Save it. `fluentcart` should show a green status in **Settings → MCP**; then ask the verification
question.

</Tab>
<Tab value="VS Code">

Run **MCP: Add Server** from the Command Palette for a guided setup, or create
`.vscode/mcp.json` for the current workspace:

```json
{
  "servers": {
    "fluentcart": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"]
    }
  }
}
```

Use **MCP: List Servers** to start or inspect `fluentcart`, then ask the verification question in
GitHub Copilot Chat. Current VS Code releases expose MCP tools from the Chat view; this recipe does
not require a special Agent-only mode.

</Tab>
<Tab value="Windsurf">

Open the **MCPs icon** in the Cascade panel, or go to **Devin Settings → Cascade → MCP Servers**.
For manual configuration, edit `~/.codeium/windsurf/mcp_config.json` and add:

```json
{
  "mcpServers": {
    "fluentcart": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"]
    }
  }
}
```

Save the file, return to **MCP Servers**, confirm `fluentcart` is enabled, and ask the verification
question.

</Tab>
<Tab value="ChatGPT web">

ChatGPT web does not read `~/.codex/config.toml` or start local commands. Use the
[ChatGPT web Secure MCP Tunnel guide](/docs/fluentcart-mcp/deployment#chatgpt-web-with-secure-mcp-tunnel)
for the private connection, its separate OpenAI permissions, and the verification sequence.

</Tab>
<Tab value="Docker">

Docker is for an always-on HTTP server, not a prerequisite for local clients. It supplies its own
Node runtime. Follow the [Deployment Guide](/docs/fluentcart-mcp/deployment#docker-image) for the
private HTTP profile, bearer key, and Host and Origin allowlists.

</Tab>
</Tabs>

## Decide What It Can See

Two independent switches. Neither has to be touched to get a working read-only server, which is why none of the configs above mention them.

**`--mode`** decides how tool definitions are presented. The default is `dynamic`: three compact
read tools search the catalogue, describe a result and execute it. Enabling reversible writes adds
one write executor, for four tools in total. Every other mode draws from the same filtered registry,
so no mode can widen what is exposed.

| Mode | What your AI sees |
|---|---|
| `dynamic` *(default)* | Three read tools; four when reversible writes are enabled |
| `curated` | A hand-picked shortlist of the tools most workflows actually need |
| `code` | Two tools over a read-only WebAssembly sandbox: `fluentcart_search_api` and `fluentcart_execute_code` |
| `full` | Every exposed definition registered up front |

**`FLUENTCART_WRITE_MODE`** decides what is in that registry at all. It accepts `disabled` or
`reversible` and defaults to `disabled` — reads only. `reversible` adds creating and updating
products, variants, coupons, customers, shipping rules, tax rules, attributes and order bumps.
Refunds and subscription cancellation are not product tools in this release.

Deletions, bulk operations, order status changes, marking an order paid and anything that moves money are not exposed in any mode. FluentCart offers no supported way to undo them, so they are not classed as reversible. See the [Tool Reference](/docs/fluentcart-mcp/tools) for the full picture.

```json
{
  "mcpServers": {
    "fluentcart": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp", "--mode", "curated"],
      "env": {
        "FLUENTCART_WRITE_MODE": "reversible"
      }
    }
  }
}
```

<Callout type="info" title="It Checks Your Store First">
At startup the server reads your site's REST index to find out which FluentCart routes exist, rather than trusting a version string. If it can't reach the site, or the store won't say what it supports, that's a startup error in your client's MCP log — not a server that connects cheerfully and then 404s on everything.

That evidence then prunes the tool list: a tool with no supported route is never registered. So the tools your AI can see are the ones your store can actually serve, and two stores running different FluentCart builds legitimately offer different tool lists.
</Callout>

## Multiple Stores

Managing more than one store? Create separate MCP server entries:

```json
{
  "mcpServers": {
    "store-production": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"],
      "env": {
        "FLUENTCART_URL": "https://shop.example.com",
        "FLUENTCART_USERNAME": "admin",
        "FLUENTCART_APP_PASSWORD": "xxxx xxxx xxxx xxxx"
      }
    },
    "store-staging": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"],
      "env": {
        "FLUENTCART_URL": "https://staging.example.com",
        "FLUENTCART_USERNAME": "admin",
        "FLUENTCART_APP_PASSWORD": "yyyy yyyy yyyy yyyy"
      }
    }
  }
}
```

Tell the AI which store you mean: "Check orders on production" or "Create a test product on staging."

## Test the Connection

Ask your AI:

> "Show me the FluentCart dashboard stats"

See store data? That client has completed a live connection. If not, head to [Troubleshooting](/docs/fluentcart-mcp/troubleshooting).
