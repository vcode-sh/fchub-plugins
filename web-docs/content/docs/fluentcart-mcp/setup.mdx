Five minutes. Generate a password in WordPress, paste a config snippet into your AI client, done. Three paths depending on how much you enjoy terminals.

## Generate an Application Password

Every setup path needs this. It's how the MCP server authenticates with your store — no actual login password involved.

<Steps>
<Step>

**Go to WordPress admin → Users → Profile**

Scroll down to the **Application Passwords** section. Type a name — `FluentCart MCP` works — and click **Add New Application Password**.

</Step>
<Step>

**Copy the password immediately**

It looks like this: `aBcD eFgH iJkL mNoP qRsT uVwX`

<Callout type="warn" title="One Chance">
WordPress shows this password exactly once. Close the page without copying and you'll need to generate a new one.
</Callout>

</Step>
<Step>

**Have your three values ready**

| Value | Example |
|-------|---------|
| **WordPress URL** | `https://your-store.com` |
| **Username** | `admin` |
| **Application Password** | `aBcD eFgH iJkL mNoP qRsT uVwX` |

The URL is the root of your site — no trailing slash, no `/wp-admin/`, no `/wp-json/`. The username is your WordPress login name, not your display name.

<Callout type="info" title="Least Privilege Works Fine">
The server inherits whatever that WordPress user can do and nothing more, so a store-manager-style role with FluentCart permissions is a perfectly sensible choice — you don't have to hand your AI the keys to the entire site. A user with no FluentCart permissions at all will collect 403s, which is the system working as designed rather than a bug. Pair a narrow role with the default read-only write mode and the blast radius is roughly zero.
</Callout>

</Step>
</Steps>

## Pick Your Path

Three ways to connect, from easiest to most manual.

<Tabs items={['Claude Desktop Extension', 'Setup Wizard', 'Manual Config']}>
<Tab value="Claude Desktop Extension">

No terminal. No JSON. No Node.js. Download a file, double-click it, fill in three fields.

**1. Download <McpbDownload />** from the latest release.

**2. Double-click the file.** Claude Desktop picks it up automatically. Or drag it into the app, or go to **Settings → Extensions → Install Extension**.

**3. Enter your credentials** — WordPress URL, username, and Application Password.

**4. Open a new chat** and try: *"Show me today's orders"*

See store data? Done.

<Callout type="info" title="Claude Desktop Only">
The extension only works with Claude Desktop. For other AI clients, use the Setup Wizard or Manual Config tabs.
</Callout>

</Tab>
<Tab value="Setup Wizard">

A guided terminal walkthrough. Asks three questions, tests the connection, saves the config.

<Callout type="info" title="Requires Node.js 24+">
Check with `node --version`. Don't have it? Grab it from [nodejs.org](https://nodejs.org).
</Callout>

**Run this:**

```bash
npx fluentcart-mcp setup
```

It looks like this:

```
┌  fluentcart-mcp setup
│
◇  WordPress URL
│  https://your-store.com
│
◇  WordPress username
│  admin
│
◇  Application Password
│  ••••••••••••••••••••••••
│
◇  Connected to Your Store Name
│
◇  Config written to ~/.config/fluentcart-mcp/config.json
│
└  You're all set. Run fluentcart-mcp to start the server.
```

If the credentials are wrong, it tells you why and offers to retry. If they work, it saves a config file at `~/.config/fluentcart-mcp/config.json`. After that, your AI client configs don't need credentials at all — the MCP server reads them from the saved file.

**Then configure your AI client** using the simplified snippet (no env vars needed):

```json
{
  "mcpServers": {
    "fluentcart": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"]
    }
  }
}
```

Where to paste this depends on your client — see the Manual Config tab for the exact location.

</Tab>

<Tab value="Docker">

For a persistent endpoint that remote clients (ChatGPT, custom agents, other machines) can reach. No Node.js needed.

```bash
docker run -d \
  -p 3000:3000 \
  -e FLUENTCART_URL=https://your-store.com \
  -e FLUENTCART_USERNAME=admin \
  -e FLUENTCART_APP_PASSWORD="aBcD eFgH iJkL mNoP qRsT uVwX" \
  -e FLUENTCART_MCP_API_KEY="$(openssl rand -hex 32)" \
  --name fluentcart-mcp \
  vcodesh/fluentcart-mcp
```

Your endpoint is at `http://localhost:3000/mcp`. Verify with `curl http://localhost:3000/health`.

For remote access, put it behind a reverse proxy or Cloudflare Tunnel — the [Deployment Guide](/docs/fluentcart-mcp/deployment) covers the details.

<Callout type="warn" title="FLUENTCART_MCP_API_KEY is not optional here">
The container binds beyond loopback, so the server checks the bearer key before it listens and exits with an error if the key is missing or shorter than 32 characters. A container that keeps restarting with `Refusing to bind 0.0.0.0` in its logs is telling you exactly this. Generate one properly — `openssl rand -hex 32` — and keep it out of your shell history.
</Callout>

## Decide What It Can See

Two independent switches. Neither has to be touched to get a working read-only server, which is why none of the configs above mention them.

**`--mode`** decides how the tool definitions are presented. The default is `dynamic`: five meta-tools your AI uses to search the catalogue, read the schema of whatever it found, and then execute it. Every other mode draws from the same filtered registry, so no mode can widen what is exposed.

| Mode | What your AI sees |
|---|---|
| `dynamic` *(default)* | Five meta-tools: `fluentcart_search_tools`, `fluentcart_describe_tools`, `fluentcart_execute_read_tool`, `fluentcart_execute_reversible_write`, `fluentcart_execute_guarded_write` |
| `curated` | A hand-picked shortlist of the tools most workflows actually need |
| `code` | Two tools over a read-only WebAssembly sandbox: `fluentcart_search_api` and `fluentcart_execute_code` |
| `full` | Every exposed definition registered up front |

**`FLUENTCART_WRITE_MODE`** decides what is in that registry at all. It defaults to `disabled` — reads only. `reversible` adds the writes that can be undone: creating and updating products, variants, coupons, customers, shipping rules, tax rules, attributes and order bumps. `guarded` is accepted and exposes exactly the same set in 2.0.0, because the two tools it exists for are not available in this release — see [No refunds or cancellations](/docs/fluentcart-mcp/deployment#refunds-and-cancellations-in-2-0-0).

Deletions, bulk operations, order status changes, marking an order paid and anything that moves money are not exposed in any mode. FluentCart offers no supported way to undo them, so they are not classed as reversible. See the [Tool Reference](/docs/fluentcart-mcp/tools) for the full picture.

```json
{
  "mcpServers": {
    "fluentcart": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp", "--mode", "curated"],
      "env": {
        "FLUENTCART_WRITE_MODE": "reversible"
      }
    }
  }
}
```

<Callout type="info" title="It Checks Your Store First">
At startup the server reads your site's REST index to find out which FluentCart routes exist, rather than trusting a version string. If it can't reach the site, or the store won't say what it supports, that's a startup error in your client's MCP log — not a server that connects cheerfully and then 404s on everything.

That evidence then prunes the tool list: a tool with no supported route is never registered. So the tools your AI can see are the ones your store can actually serve, and two stores running different FluentCart builds legitimately offer different tool lists.
</Callout>

## Multiple Stores

Managing more than one store? Create separate MCP server entries:

```json
{
  "mcpServers": {
    "store-production": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"],
      "env": {
        "FLUENTCART_URL": "https://shop.example.com",
        "FLUENTCART_USERNAME": "admin",
        "FLUENTCART_APP_PASSWORD": "xxxx xxxx xxxx xxxx"
      }
    },
    "store-staging": {
      "command": "npx",
      "args": ["-y", "fluentcart-mcp"],
      "env": {
        "FLUENTCART_URL": "https://staging.example.com",
        "FLUENTCART_USERNAME": "admin",
        "FLUENTCART_APP_PASSWORD": "yyyy yyyy yyyy yyyy"
      }
    }
  }
}
```

Tell the AI which store you mean: "Check orders on production" or "Create a test product on staging."
