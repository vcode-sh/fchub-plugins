Something's not working. It happens. Every failure mode encountered (and reported by users) is catalogued here so you can fix it without filing an issue. Most problems are one of three things: connection, authentication, or timeouts.

## Quick Diagnosis

Before you do anything else, run this in your terminal:

```bash
curl -u "username:application_password" https://your-store.com/wp-json/fluent-cart/v2/app/init
```

Replace `username` and `application_password` with your actual values. What you get back tells you exactly where the problem is:

| Response | What It Means |
|----------|---------------|
| JSON with store data | Connection and auth work fine. Your issue is in the AI client config. |
| `401 Unauthorized` | Wrong username or Application Password. |
| `403 Forbidden` | That user lacks the FluentCart permission behind this endpoint. |
| `404 Not Found` | FluentCart isn't installed, or the URL is wrong. |
| Connection refused | WordPress is unreachable. Network or server issue. |

## Common Issues

<Accordions type="multiple">
<Accordion title="Server Not Starting / No Tools Appearing">

**What you see**: Claude Desktop has no hammer icon. Cursor shows a red dot. The AI says it can't find any FluentCart tools.

**What's actually wrong** (in order of likelihood):

1. **Node.js missing or too old**
   ```bash
   node --version
   ```
   The MCP server needs `v22.0.0` or higher. If you don't have Node at all, get it from [nodejs.org](https://nodejs.org). If you have an older version, upgrade. No apologies for requiring modern JavaScript.

2. **npx not found**
   It comes with Node.js. If `which npx` returns nothing, your Node installation is broken. Reinstall.

3. **JSON syntax error**
   The number one cause of "it just doesn't work." A trailing comma, a missing quote, a rogue bracket. Paste your config into [jsonlint.com](https://jsonlint.com) and see what it says. Nobody can debug your JSON for you.

4. **Wrong config file location**
   - Claude Desktop (macOS): `~/Library/Application Support/Claude/claude_desktop_config.json`
   - Claude Desktop (Windows): `%APPDATA%\Claude\claude_desktop_config.json`
   - Cursor: Check **Settings → MCP** for the path

5. **Didn't restart the app**
   Claude Desktop, Cursor, and VS Code don't hot-reload MCP configs. Close the app completely (not just the window — quit it) and reopen.

6. **The store rejected the startup check**
   Before serving anything, the server asks your site which FluentCart routes exist. Bad URL, bad credentials or an unreachable site and it stops there rather than connecting and failing on every call afterwards. The error lands in your client's MCP log.

</Accordion>
<Accordion title="A Tool I Expected Isn't There">

**What you see**: The AI says it has no tool for creating a product, updating a status, or refunding. Search comes back empty for something the [Tool Reference](/docs/fluentcart-mcp/tools) clearly lists.

**What's wrong**: It isn't hidden — it isn't registered. Exposure is decided before registration, so a tool your policy excludes cannot be listed, searched, described or called by name.

**Fix**, in order of likelihood:

1. **Write mode.** `FLUENTCART_WRITE_MODE` defaults to `disabled`. Creating or updating something needs `reversible`.
2. **It isn't exposed in any mode.** Refunds, subscription cancellation, every deletion, bulk actions, order status changes, marking an order paid and dispute handling are absent from all three write modes — including `guarded`, which in 2.0.0 exposes exactly what `reversible` does. No environment variable brings them back. [Why](/docs/fluentcart-mcp/deployment#refunds-and-cancellations-in-2-0-0).
3. **Your store doesn't serve that route.** Startup discovery prunes the registry: a tool whose endpoint your FluentCart build doesn't expose is never registered, and a tool that needs several routes needs all of them. A Pro-only endpoint on a core-only site is legitimately absent, and installing the missing component brings the tool back on the next restart.
4. **It never existed.** Subscription pause, resume and reactivate are not tools. Neither is a customer address dropdown helper. Check the reference rather than the AI's optimism.

The tool list is therefore a property of your store, not a fixed catalogue. Two sites on different FluentCart builds will legitimately show different tools, and the reference page lists what ships rather than what any particular store exposes.

</Accordion>
<Accordion title="Setting the Guard Variables Did Nothing">

**What you see**: You set `FLUENTCART_WRITE_MODE=guarded`, generated a signing secret, mounted a state directory — and no refund or cancellation tool appeared. No error either.

**That's correct.** Those two tools are absent from every write mode in 2.0.0. `guarded` is a valid setting that currently exposes exactly what `reversible` does, and `FLUENTCART_GUARD_SECRET`, `FLUENTCART_GUARD_STATE_DIR` and `FLUENTCART_ALLOW_LIVE_GATEWAY_ACTIONS` are reserved for the release that brings them back. Setting them today changes nothing at all.

The guard is finished and tested; what's missing is proof it survives contact with a real store, which FluentCart 1.5.5 makes impossible to gather cleanly. The [deployment guide explains it properly](/docs/fluentcart-mcp/deployment#refunds-and-cancellations-in-2-0-0). If you need refunds automated, this release is not the tool for it.

</Accordion>
<Accordion title="401 From the MCP Endpoint Itself">

**What you see**: `{"error":"Unauthorized"}` from your own HTTP deployment, not from WordPress.

**What's wrong**: The bearer key. Every rejection returns that identical body — missing header, malformed header, wrong key, all the same. That's deliberate: a prober shouldn't be able to tell which mistake they made. It does mean you can't debug it by reading the response, so check the client config instead.

Requests need `Authorization: Bearer <key>` matching `FLUENTCART_MCP_API_KEY` exactly. Watch for a trailing newline from `echo` when you set it in a shell.

If the container won't start at all and the logs say `Refusing to bind`, the key is missing or under 32 characters. The server checks before it listens, so there is no window where the endpoint exists unprotected.

</Accordion>
<Accordion title="RESPONSE_TOO_LARGE">

**What you see**: A tool call fails with `RESPONSE_TOO_LARGE` instead of returning data.

**What's happening**: The response exceeded the budget, and the server would rather refuse than hand your model a payload that has been quietly trimmed and looks complete. The error names the ways out.

**Fix**: Narrow the request. A smaller `per_page`, a tighter date range, a specific ID instead of a list. "Show me every order ever placed" is not a question with a useful answer anyway.

</Accordion>
<Accordion title="Authentication Failed (401)">

**What you see**: Errors about "authentication failed", "invalid credentials", or HTTP 401.

**What's actually wrong:**

1. **Wrong Application Password**
   The password has spaces between groups: `aBcD eFgH iJkL mNoP`. Include the spaces. It's case-sensitive. Copy it exactly.

2. **Wrong username**
   Use the WordPress login name, not the display name. If your display name is "John Smith" but your login is "john", use `john`. Check **Users → Profile** in WordPress admin.

3. **Application Passwords disabled**
   Security plugins love disabling things. Wordfence, iThemes Security, Solid Security — any of them might have turned off Application Passwords. Check your security plugin settings.

   Some managed hosts (WP Engine, Kinsta, etc.) also disable them by default. Check with your host.

4. **HTTP instead of HTTPS**
   WordPress blocks Application Passwords over plain HTTP. If you're on a local dev site, add this to `wp-config.php`:
   ```php
   define('WP_ENVIRONMENT_TYPE', 'local');
   ```

5. **Password was deleted or regenerated**
   If you made a new Application Password in WordPress, update it in your MCP config and restart the client. The old one is dead.

</Accordion>
<Accordion title="Permission Denied (403)">

**What you see**: "permission denied", "forbidden", HTTP 403.

**What's wrong**: The WordPress user the server authenticates as lacks the FluentCart capability behind that particular endpoint.

**Fix**: Go to **Users** in WordPress admin and look at what that account can do. The server inherits exactly the permissions of the user in your config — no more, no less — so a narrow role is a supported choice, not a broken one. If you want the AI to read reports but never see customer records, that's a role question, and FluentCart's own roles and permissions screens are where you answer it.

A 403 on one tool while everything else works is the system behaving correctly. A 403 on everything usually means the account has no FluentCart permissions at all.

</Accordion>
<Accordion title="Not Found (404)">

**What you see**: "not found", "route not found", HTTP 404.

**What's actually wrong:**

1. **FluentCart not installed**
   Check **Plugins** in WordPress admin. FluentCart must be installed and activated. The MCP server talks to FluentCart endpoints — if FluentCart isn't there, those endpoints don't exist.

2. **Wrong URL**
   The URL should be the root of your WordPress site:
   - Correct: `https://shop.example.com`
   - Wrong: `https://shop.example.com/wp-admin/`
   - Wrong: `https://shop.example.com/wp-json/`
   - Wrong: `https://shop.example.com/` (trailing slash is technically fine, the server strips it)

3. **Permalinks set to "Plain"**
   WordPress REST API needs pretty permalinks. Go to **Settings → Permalinks** and pick literally anything except "Plain". Hit Save even if you don't change anything — this flushes rewrite rules.

4. **REST API blocked**
   Security plugins and `.htaccess` rules sometimes block `/wp-json/`. Check your security plugin settings and server config.

</Accordion>
<Accordion title="Timeout Errors">

**What you see**: Requests die after 30 seconds. "timeout", "aborted", "ETIMEDOUT".

**What to do:**

1. **Increase the timeout**
   The default is 30 seconds. If your server is slow, bump it up via the `FLUENTCART_TIMEOUT` env var (milliseconds):
   ```json
   "env": {
     "FLUENTCART_URL": "https://your-store.com",
     "FLUENTCART_USERNAME": "admin",
     "FLUENTCART_APP_PASSWORD": "...",
     "FLUENTCART_TIMEOUT": "60000"
   }
   ```

2. **Check your server**
   Run `curl https://your-store.com/wp-json/`. If curl also hangs, that's a network or server problem. Not something the MCP server can fix.

3. **Ask for less data**
   Listing 10,000 orders in one request will be slow on any server. Use pagination — "Show me the last 10 orders" instead of "Show me all orders." Every list tool supports `per_page` and `page` parameters for exactly this reason.

</Accordion>
<Accordion title="AI Ignores FluentCart / Won't Use Tools">

**What you see**: The AI doesn't mention FluentCart. It says it can't access your store. It just... doesn't use the tools.

**What's happening:**

1. **Server not connected**
   Verify the connection:
   - Claude Desktop: **Settings → Developer** — is `fluentcart` green?
   - Cursor: **Settings → MCP** — green dot = connected
   - Claude Code: `claude mcp list`

2. **Too many MCP servers**
   Some clients choke when you have 15 MCP servers connected. Try disabling the ones you're not using right now.

3. **Wrong mode**
   - VS Code Copilot: You must be in **Agent** mode. Regular Chat won't use MCP tools. That's Microsoft's design choice.
   - Some clients have "tool use" toggles — make sure it's on.

4. **The AI just needs a nudge**
   Sometimes the AI doesn't realise it has FluentCart tools until you mention them explicitly: "Use the FluentCart tools to show me my recent orders." After the first use, it remembers.

</Accordion>
<Accordion title="SSL / Certificate Errors">

**What you see**: UNABLE_TO_VERIFY_LEAF_SIGNATURE, certificate chain errors, SSL handshake failures.

**What to do:**

1. **Self-signed certs (local dev)**
   If your local WordPress has a self-signed cert, add this env var:
   ```json
   "env": {
     "NODE_TLS_REJECT_UNAUTHORIZED": "0"
   }
   ```

   <Callout type="warn" title="Local Development Only">
   Do not use this in production. It disables all SSL verification. You know this, but I'm contractually obligated to say it.
   </Callout>

2. **Cloudflare issues**
   If you're behind Cloudflare with "Full (strict)" SSL, your origin server needs a valid cert. "Full" (without strict) is more forgiving.

</Accordion>
<Accordion title="Prices Look Insane">

**What you see**: A $49.99 product shows as 4999. Totals are 100x too large.

**That's correct.** FluentCart stores money in the smallest currency unit — cents, pence, grosze. 4999 = $49.99. 10000 = €100.00. 4000 = 40.00 PLN.

The AI usually converts these for you. If it doesn't, tell it: "Show prices in dollars, not cents." The currency format is documented in every tool description so the AI knows to convert, but occasionally it shows the raw value.

</Accordion>
<Accordion title="Known FluentCart Bugs (Upstream)">

Some things break because of upstream FluentCart issues, not the MCP server. They're documented here so you don't file a bug report that can't be fixed from the MCP side.

**Attribute Term Creation** — `POST /options/attr/group/:id/term` returns "Information mismatch". FluentCart queries the wrong table when validating. Create terms via the admin UI instead.

**Variant Listing Without Product ID** — Calling `variant_list` without a `product_id` crashes the server. Use `product_pricing_get` to list variants for a specific product instead.

**Price 100x Multiplier** — FluentCart's `Helper::toCent()` multiplies by 100 again internally. When passing prices via MCP, pass them in cents (e.g. 4999 for $49.99) — the API handles the rest. If prices look 100x too large, this is why.

**Some Report Endpoints Missing** — A handful of report routes (`cart-report`, `order-value-distribution`, `sales-report`, `license-chart`, `license-pie-chart`) don't exist on older FluentCart builds. On such a store those tools are pruned at startup rather than offered and failed, so the symptom is a missing tool, not an error. This release is verified against FluentCart 1.5.5 with Pro 1.5.4 on WordPress 7.0.2. Each affected tool's description names an alternative.

**Customer Address Select** — The old `customer_address_select` endpoint is scoped to frontend sessions with cookie auth, not the REST API, so the tool wrapping it has been removed rather than left in to fail politely. Use `fluentcart_customer_addresses` and filter client-side.

For the full list of 14 documented upstream bugs, check the [GitHub repository](https://github.com/vcode-sh/fchub-plugins/issues).

</Accordion>

## Still Stuck?

Before filing an issue, check the Known FluentCart Bugs section above — your problem might be upstream.

If none of the above helps:

1. Check [GitHub Issues](https://github.com/vcode-sh/fchub-plugins/issues) — someone might've hit the same problem
2. Open a new issue with: error message, Node.js version, AI client name, and what you tried
3. Do not include your Application Password in the issue. Nobody wants it
