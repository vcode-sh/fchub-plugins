Membership emails should feel like part of the experience, not an automated
receipt from a printer that has seen things.

Notification Studio gives every membership moment a clear delivery choice:
send a built-in branded email, use a FluentCRM automation, or keep it off.

## Open Notification Studio

Go to **Memberships > Settings > Email Studio**.

The overview groups messages into Access, Membership lifecycle, Trials, and
Content. You can see what is active before opening an individual email.

## Design a built-in email

<Steps>
<Step>

**Choose the delivery**

Select **Built-in email** for a message designed and sent by Memberships.
When FluentCRM is active, you can choose **FluentCRM automation** instead.
Choose **Off** when that moment should stay quiet.

</Step>
<Step>

**Write the subject and preview text**

Use member, plan, date, and link variables to keep one template useful for
every recipient.

</Step>
<Step>

**Build the message**

Add text, headings, buttons, images, dividers, spacing, and member data blocks.
Reorder the content until it reads like a useful email rather than a settings
dump wearing a logo.

</Step>
<Step>

**Preview realistic data**

The preview replaces variables with representative member and plan values so
you can catch awkward gaps before a customer does.

</Step>
<Step>

**Send a test**

Send the current message to a test address and check it in a real inbox. Save
when the subject, links, and layout behave.

</Step>
</Steps>

## Share a brand style

The brand template controls the common shell used by built-in messages:
colours, logo, typography, background, content width, and footer presentation.

Individual emails can follow the shared style or override it when a particular
message needs a different treatment. Change the shared template once and the
other built-in emails keep their content while adopting the new look.

## Choose Memberships or FluentCRM

<Accordions type="single">
<Accordion title="Use the built-in email when…">

- the message is transactional and closely tied to access;
- you want a visual editor without building an automation;
- a direct preview and test-send flow is enough;
- the site does not use FluentCRM.

</Accordion>
<Accordion title="Use FluentCRM when…">

- the message belongs to a longer onboarding, renewal, or win-back journey;
- delivery depends on tags, segments, delays, or branching;
- you want other customer data in the same automation;
- your team already manages communication in FluentCRM.

Changing delivery does not change the membership event itself. It only decides
who owns the message.

</Accordion>
</Accordions>

## If an email does not arrive

1. Check that the message is set to **Built-in email**, not **Off** or
   **FluentCRM automation**.
2. Send a test from Email Studio.
3. Check **Tools > Scheduled Actions** for a failed Memberships email.
4. Verify that normal WordPress email works with your mail provider.
5. Confirm that the sender domain has the authentication your provider expects.

For deeper diagnosis, continue to
[Troubleshooting](/docs/fchub-memberships/troubleshooting#email-issues).
