FluentCommunity spaces and courses. Community access follows the membership
instead of relying on a weekly “who should still be in here?” ritual.

## Add Community access to a plan

<Steps>
<Step>

**Check provider health**

Open **Memberships > Integrations**. Confirm that FluentCommunity is active and
that the capability you need is available.

</Step>
<Step>

**Edit the membership plan**

In **Choose content access**, select a FluentCommunity space or course and find
the exact resource by name.

</Step>
<Step>

**Review and save**

The Community resource appears alongside WordPress content in the plan
summary. Save the plan and test it with a real member account.

</Step>
<Step>

**Inspect the member**

Open **Memberships > Members** and select the member. Their profile shows the
available Community context and any pending provider work.

</Step>
</Steps>

## Health and recovery

Memberships records the intended Community change before applying it. If the
provider is unavailable or refuses the operation, the issue remains visible
instead of being quietly converted into optimism.

The Integrations workspace can:

- show whether core and optional Pro capabilities are available;
- identify pending or failed Community operations;
- preview differences between membership access and provider state;
- repair supported differences in bounded batches;
- keep manual or separately-owned access intact.

<Accordions type="single">
<Accordion title="What if FluentCommunity is inactive?">

The base membership remains recorded and WordPress content continues to work.
Community-specific work stays visible for recovery after the provider returns.

</Accordion>
<Accordion title="Why are some Pro controls hidden?">

Optional controls appear only when the installed FluentCommunity Pro version
and runtime contract support them. A feature that cannot run is not improved by
leaving a confident-looking dropdown behind.

</Accordion>
<Accordion title="Does removing one purchase always remove Community access?">

No. Memberships keeps separate ownership for separate access sources. Removing
one source does not remove provider access while another valid membership or
manual source still owns it.

</Accordion>
</Accordions>
